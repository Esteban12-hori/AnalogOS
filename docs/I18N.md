# Interface languages (EN | ES)

AnalogOS is **English by default** and has an **EN | ES** selector in the top bar. English is the source language and the only language of records and exports (ADR-016). Spanish is a **presentation-only** layer (ADR-017, proposed). This guide is the i18n contract: rules, API, conventions, what is never translated, the **ownership table** for the parallel areas (§7) and how cross-area text is integrated (§11). Code: `apps/web/src/i18n/`. No npm dependency: the layer is hand-written and offline.

**Status (2026-11-15, branch `feature/es-selector`):** base and the three areas (ui-core, mission-ui, ai-science) integrated. Explore, place sheet and tabs, rail, metrics, leader lines, globe and 2D map, composer, “Your mission”, planner, result, print report, Reading, geology card and the AI draft language are available in Spanish; English output unchanged. Review fixes applied the same day: the MapLibre canvas name follows the language, event-written live regions are emptied on a language change, Spanish-only truncations at 360–1440 px removed, and the snapshot error screen maps the loader's own messages (other details marked `lang="en"`). ADR-017 is still **proposed** (pending review).

## 1. Rules that are never broken

- **Presentation only.** Formulas, weights, thresholds, ranking, place order, statuses and results are identical in both languages. No collator, sort or tie-break may depend on the language.
- **Records and exports do not change.** New mission evaluations/exports are 1.1.0, geology wrappers version 2, per-site geology exports version 2, English, byte-for-byte identical in EN and ES (tested). Never call the engine with `version: '1.0.0'` or geology version 1 to “get Spanish”: those versions are for historical reconstruction only.
- **Data is not translated:** JSON exports and their notices, contracts/schemas, IDs (`site_id`, `requirement_id`, `ref_id`, `evidence_id`), enum codes (`cumple`, `priorizado_para_reconocimiento`, `needs_calibration`), URL values (`?modo=mision`), storage keys, filenames of downloads, dataset names, official unit names and citations.
- **Artifacts are untouchable** (`artifacts/**`). Their Spanish evidence is shown as is in Spanish and through `sourceText`/`geologyGloss` in English (§6).
- **Faithful, prudent wording:** this is a preliminary screening. “Requires review”, “does not authorize”, “approximate”, “not calibrated”, “proxy” never become “aprobado”, “seguro”, “validado” or “apto”. Reuse the pre-ADR-016 Spanish (git `273e5f8`, same file and place) whenever it exists.
- **AI never produces figures or ordering.** Its only language input is the optional `language` of the draft operation (§7, ai-science).
- **Accessibility:** `<html lang>` always correct; changing language never moves focus; `aria-label`, `title`, `alt`, `sr-only` text and announcements are translated like visible text.
- **No secrets** in catalogs, tests or fixtures.

## 2. Current language

| Start-up priority | Source |
|---|---|
| 1 | `?lang=en` or `?lang=es` (case-insensitive; other values ignored) |
| 2 | `localStorage['analogos:lang']` (written only by an explicit choice in the selector) |
| 3 | `en` |

- The selector stores the choice. If the URL already carries `?lang=`, it is rewritten with `replaceState` (the URL wins on reload); otherwise the URL is left clean.
- `<html lang>` is set by the inline `<head>` script before the first frame and kept in sync by the store; `<meta name="description">` follows the language.
- Without storage (private mode, `file://`) everything works; the choice lasts for the session.
- Selector (`LanguageSwitch`): a `role="group"` named “Language”/“Idioma” with two toggle buttons (`aria-pressed`), each with `lang` and its own-language name (“English”, “Español”); visible focus ring; ≥44 px touch target on coarse pointers; the change is announced in the single live region in the new language. It sits in `.topbar-end` next to the status chip and never displaces the logo (the wordmark hides ≤540 px, the emblem always stays; verified at 360–1440 px).

### 3.1 Language store

```ts
type Locale = 'en' | 'es'
getLocale(): Locale
setLocale(next, { persist = true, updateUrl = true })
subscribeLocale(listener): () => void
useLocale(): Locale        // useSyncExternalStore: re-renders on change
LOCALES, DEFAULT_LOCALE ('en'), LOCALE_NAMES, INTL_LOCALE ({ en: 'en-US', es: 'es-CL' })
```

### 3.2 Catalogs and `t()`

```ts
// i18n/messages/places.ts — one file per catalog, English and Spanish side by side
import { defineMessages } from '../translate'
export const tPlaces = defineMessages({
  en: { 'rail.title': 'Places', 'rail.count': { one: '{count} place', other: '{count} places' } },
  es: { 'rail.title': 'Lugares', 'rail.count': { one: '{count} lugar', other: '{count} lugares' } },
})

const t = useT(tPlaces)            // in a component: subscribed; identity changes only with the language
t('rail.count', { count: 3 })      // “3 places” / “3 lugares”
tPlaces('rail.title')              // in a pure function: reads the current language when called
tPlaces.in('es')('rail.title')     // fixed language (static HTML, Node, tests)
```

- **Types:** an unknown key does not compile; a plural without `{ count }` does not compile; a Spanish catalog with a missing key, an extra key or another shape (text vs plural) does not compile (`catalogParity.typecheck.ts` proves it in `tsc`).
- **Placeholders** `{name}`: same set in en and es (test). A missing variable stays visible as `{name}`. Numeric variables are printed in the language's format, ≤3 decimals, **no grouping** (a year stays “2024”). Format scores, areas and percentages first (§3.3) and pass the text.
- **Plurals:** `{ one, other }`; `one` only when `count` is ±1. If Spanish needs a plural where English does not, write the English one as a plural with two identical forms.
- **Runtime fallback:** a key missing through a cast falls back to English, then to the key.

| Function | en | es |
|---|---|---|

| `formatScorePercent(94.87)` | 94.9% | 94,9 % |
| `formatDecimal(1234.56)` (≤1 decimal) | 1,234.6 | 1.234,6 |

| `formatArea(447.3)` | ≈ 450 km² | ≈ 450 km² |
| `formatMonthYear('2025-03-01')` (UTC) | Mar 2025 | mar 2025 |
| `formatDate`, `formatTime` | Intl en-US | Intl es-CL |
| `formatList(['A','B','C'])` | A, B, and C | A, B y C |

- The English output is **byte-identical** to `domain/formatting.ts` today (tested), so `domain/formatting.ts` can delegate to these functions without changing a single English string. Every function takes an explicit `locale` last.
- **Never** use them in exports, contracts, fingerprints, record text or AI payloads.
- Mission UI formatting from structured data (conditions, quantities, observed values, importance/scale labels) uses the record pack of the language: `displayMissionPack(locale).describeEffective(r)`, `.fmtObserved(v, u)`, `.importanceLabel[x]`… (en-US / es-CL hand-rolled, identical in Node and browser). Geology coverage/scale labels: `displayGeologyPack(locale).formatCoverage(f)`.

## 4. Conventions

1. **Catalog per area**, file `i18n/messages/<name>.ts`, exporting one `t<Name>` translator. Only the owning area edits it (§7). To use another area's text, import its translator read-only; if a key is missing there, add it to your own catalog and report it.
2. **Keys:** flat, dotted, prefixed by component: `'rail.title'`, `'detail.tabs.method'`, `'aria.closePlace'`. **English = current text verbatim** (existing English tests must stay green untouched). Spanish = pre-ADR-016 wording at the same place (`git show 273e5f8:<path>`), else the reviewed `feature/i18n` translation (`git show feature/i18n:apps/web/src/i18n/messages/<area>.es.ts`), else a careful translation under §1. **Exception:** when the old wording loses words to an ellipsis where the English fits, a shorter faithful wording is used and the old one is quoted in a comment next to the key. Current cases: the dock prompt `composerPrompt` «Describe tu prueba para Marte…» (was «Describe la prueba que quieres hacer para Marte…», cut before «Marte» at 360 px), the ◆ card `meta.notFromSearch` « · fuera de la búsqueda» (was «no sale de la búsqueda», cut at 1440 px; the group label follows) and `analog.noRanking` «sin %, sin puesto» (was «sin ranking»; «Fuente: …» was cut at 360 px).
3. **Components:** call `useT(tX)` or `useLocale()` even though `App.tsx` subscribes at the root (memoized children are not re-rendered). Put `locale`/`t` in the dependencies of `useMemo`/`useCallback`/`useEffect` that produce text.
4. **Pure functions** that build text take `locale: Locale = getLocale()` as the last optional parameter (as `bootLines`, `chipText`, `snapshotAnnouncement`, `dataAttributionText`), so they are testable in both languages.
5. **Imperative DOM** (globe labels, leader-line canvas, `SignalCard`, MapLibre): subscribe with `subscribeLocale` or include `locale` in the effect that draws, and redraw on change. MapLibre names its focusable canvas (`role="region"`, default “Map”) only when the map is built: `CandidateFlatMap` passes `locale: mapUiStrings(locale)` to the constructor and renames the canvas in an effect on `[locale]` (“Map” / “Mapa”).
6. **Canonical state:** store data in canonical form (English record text, Spanish artifact text, user text as typed) and translate **only when showing** it. Never store translated text in state or in a record: switching language after loading or evaluating must not leave stale text.
   - **Mission messages** (planner issues, notices, controller errors, geometry validation, `draft`/`explain` messages, warnings, the deterministic “The brief mentions …” open question) are stored in canonical English (`canonicalMessage`) and shown with `displayMissionMessage(text, locale)`. The two notices written by the main chunk are in `tComposer` (`notice.*`); every other template is registered by `mission/messages.ts` when its deferred chunk loads. Unknown text (server text, user and AI-drafted text) is shown unchanged.
   - **Text created from a template becomes user text.** “Use example”, the default names of new requirements (“Regional median slope”, “Unmeasured request”, topic) and the default target are created in the interface language of that moment and from then on are the user's text, like a Spanish AI draft: they are exported verbatim and not rewritten when the language changes. With the same content the JSON is identical in EN and ES (tested).
   - **Live regions written by an event** (the planner step announcement, the mobile metrics carousel) use `const [text, announce] = useLiveText()` instead of `useState('')`: the text is kept with the language it was written in and the region is emptied when the language changes (the selector already announces the new language in the global region). Re-translating it would announce the same event a second time; keeping it would leave text in the previous language. Switching back never brings the old text back.
   - **Exception (known limit):** the AI client (`mission/aiClient.ts`) builds its failure message in the interface language when the result arrives (`tAi`), and the planner/controller keep that string. After switching language, an AI error message stays in the language it was produced in until the next request. English messages produced before switching to Spanish are still mapped by `displayMissionMessage` (`mission.ts` `ai.*`). Server errors carry `code`; fixing this fully needs client-side failure codes (offline, timeout, canceled, invalid response).
7. **Glyphs and units** (●, ◆, ✓, °, km², K) are not translated; word units are (`mm/year` → `mm/año`).
8. **Proper names** are not translated: places, datasets, missions, institutions (SERNAGEOMIN, SEGEMAR, MMA).
9. **Tests:** English tests stay as they are. Add Spanish tests per area in new files (`*.es.test.ts(x)`), switching with `setLocale('es', { persist: false, updateUrl: false })` (the setup restores English after each test) or `t.in('es')`.

## 5. Record text (engine output) — `i18n/recordText`

Text written by the deterministic engine is English in the record. To SHOW it in Spanish:

```ts
import { displayRecordText, displayRecordTexts, displayVerificationText, displayMissionPack } from '../../i18n/recordText'
displayRecordText(result.reason, locale)           // also required, scale_note, conversion
displayRecordTexts(option.what_would_change, locale)
displayRecordText(evaluation.ordering_rule, locale); displayRecordTexts(evaluation.limits, locale)
displayRecordText(note, locale)                    // resolution notes, data_request.note, app-derived evidence claim
displayVerificationText(item, locale)              // |fc| = source text, |req| = record text
displayRecordText(ref.text, locale); displayRecordText(view.notice, locale); displayRecordTexts(brief.limits, locale)  // geology
```

- English returns the text unchanged. Spanish returns the frozen 1.0.0 / version 1 wording of the **same fact** (numbers re-printed es-CL exactly as the frozen pack prints them, user labels kept verbatim), or the original when the text is not a record text.
- Pass only record-authored fields. Never pass user text (labels, brief, activity, quotes, open questions), source evidence (site names, field checks, limitations, claims copied from the snapshot) or IDs — those are shown as they are (source evidence through §6).
- Short labels (importance, scale, topic) are deliberately not mapped standalone (“preference” is also an enum code); format them from structured data with `displayMissionPack(locale)`. UI-only constants that ADR-016 bound to the English pack (`STATUS_DEFINITIONS`, `LIMITS`, `PURPOSE_LABEL`, `GEOLOGY_NOTICE`) are pack sentences and map with `displayRecordText`.
- Proven by `recordText.test.ts` with the engine as oracle over the twelve `legacyCases` (evaluation, verification catalog, explanation view, geology catalog and guidance).
- The module carries the Spanish packs (~15 KB): import it only from the chunks that show records (mission, reading, metrics rail), not from the initial shell.

## 6. Scientific text of the artifacts — `i18n/science`

```ts
import { scienceText, knownSpanishLang, originalWordingMark, unitNameGloss, unitDescriptionGloss } from '../../i18n/science'
<li>{scienceText(warning, locale)}</li>                     // en: reviewed English rendering (displaySource) · es: original
<span lang={knownSpanishLang(locale)}>{description}{originalWordingMark(locale)}</span>  // known-Spanish text left in original
unitNameGloss(name, locale) ?? null                          // English gloss only in en; null in es (show the official name alone)
```

- Replace every direct `displaySource(x)` / `unitNameEn` / `unitDescriptionEn` / `ORIGINAL_WORDING_MARK` call in a component with these helpers (they keep the English behavior byte-identical).
- In Spanish: no gloss, no “English editorial translation” label, no “[original Spanish wording]” mark, no `lang="es"` (the page is Spanish). English-language source titles stay as they are (no language is guessed).
- `sourceText.ts` and `geologyGloss.ts` keep their English semantics (ai-science); their coverage tests stay as they are.

## 8. Static HTML (before React)

- `index.html` declares `<html lang="en">` and the English description (= `tShell('meta.description')`, tested).
- `localeHeadScript()` runs first in the `<head>` (before the boot script) and sets `<html lang>` with the §2 rule.
- The build writes the static shell in English; each translatable text carries `data-i18n="<key>"` (`content/shell.ts`, `staticShellText`). The data credit keeps its pinned markup and is translated by selector (`.stage-data-credit`).
- `staticLocaleScript()` right after `#root`: when the language is not English it replaces the last text node of each `data-i18n` element, marks the static selector option (`data-lang-option`) and sets the description. Boxes and classes do not change (CLS 0). No `src`/`href` added (release packager accepts it).
- A new static text must add its key to `staticShellText`; the test requires a Spanish text for every `data-i18n` key.

| User text (brief, activity, labels, details, quotes, open questions), including AI drafts | as typed/confirmed | never translated |
| AI draft language | interface language at request time | `language` field (ai-science): sent only when the interface is Spanish |
| Mission messages (planner issues, notices, controller and geometry errors, the “brief mentions” question) | canonical English | `displayMissionMessage` (§4.6) |
| AI client failure messages | interface language when the result arrived | shown as stored (known limit, §4.6) |
| Example, default requirement names and default target | interface language when created; then user text | never translated (§4.6) |
| Geology unavailability reasons | canonical English | `geologyReasonText` |
| Snapshot loader messages (`{path} could not be loaded ({status}).`, invalid context outline, unknown error) | canonical English (`data/snapshotError`) | `displaySnapshotError`: Spanish in ES |
| Contract validation details (Ajv), network errors raised by the browser | as produced (English) | shown as is; in Spanish marked `lang="en"`; the surrounding UI text is translated |

**Known limits (decisions, not bugs):** the static shell is English in the HTML and switched by script before React (no flash with JS enabled; English if inline scripts are blocked). User and AI-drafted text is not rewritten when the language changes (this includes an example or default requirement names created in the other language). An AI client error message stays in the language it was produced in. A future English record sentence without a frozen Spanish twin is shown in English in the Spanish interface (never machine-translated). The Spanish AI draft prompt is verified with a mocked provider only; a real Spanish draft has not been run against Anthropic from this branch.
