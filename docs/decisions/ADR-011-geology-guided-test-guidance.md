# ADR-011 — Test guidance with official geology and AI (opt-in channel)

- Status: **accepted** (Codex, after Claude's implementation and corrections, independent review, local QA and real verification in dev)
- Date: 2026-11-14
- Authorization: Dan: "let's have the AI use this geological data to improve the recommendations". Plan reviewed by Codex on `project/NEXT_TASK.md` (M10-GEOLOGY-AI).

## Decision

1. **Separate layer, no geological score.** Geological guidance never modifies statuses, ranking, score, confidence, weights, requirements or profiles. Regional mapping does not prove traction, soil mechanics, Martian equivalence, safety or permits; coverage is not suitability; absence is not nonexistence. A sector discarded by requirements is not rehabilitated and receives no guidance; Yungay remains REF.
2. **Closed catalog, the AI only chooses.** `shared/geology/guidance.ts` computes, from the validated official package and the recalculated evaluation, (unit | sector) pairs + purpose with `ref_id = site|geo|unit_id|purpose`. Closed purposes (seven); each one exists only if it applies to the data (gap with a zone without a polygon or not usable; ambiguity with overlap; missing description; etc.). Text from a fixed template "editorial guidance, not measurement"; the AI does not write prose or classify materials. Hard caps: 3 per sector, 12 in total, with no obligation to fill them (there is no free-form justification field: "more quota" is not possible; Claude's local decision to avoid free text). Violation = entire response discarded, without trimming or repairing its data. Only with the geological channel is a second call allowed with the same facts/schema and a controlled reminder, within the total time limit. Everything is validated again; if it fails, the error is kept. Timeout, refusal, rate limit, truncation and non-JSON output are not retried. Provenance corresponds to the accepted call; it does not add the consumption of the rejected attempt.
3. **Partial sectors keep their units.** Units from the covered area are emitted with the gap/overlap always visible; no units are located within the gap. With a point/bbox, only context from the **full window** is provided, labeled, never attributed to the small geometry; with no chosen window, no units are emitted. Floating-point noise (e.g. 1e-15 of overlap in a `available` sector) does not count: tolerance of `available` (1e-8).
4. **Opt-in channel, M8 intact.** `explain` accepts optional `geology_context_fingerprint`; the geological result is a separate block (`geology`) and the client stores a geological record separate from the M8 record (which does not change). Extended output schema (`geology_ref_ids`) only with opt-in; the field is separated before validating the M8 selection with its contract intact. `max_tokens` 6000 only with the channel (2000 truncated in the real test).
5. **Identity.** `context_fingerprint` = SHA-256 of the full canonical JSON of the validated context (`shared/mission/fingerprint.ts`); it is not presented as a byte hash. The server also compares the SHA-256 of the bytes of `candidate-details.json` with `candidates_sha256`. `subset_fingerprint` links all the exact subsets used (geometry, units, sources, citations, requests and metadata); it can be recalculated from the wrapper. `catalog_fingerprint` links that fingerprint, context, request, evaluation and references/texts. `policy_version` is not invented.
6. **Optional loading on the server.** `server/ai/geology.ts` reads the packaged file; absent = not available (M8 intact); present but invalid/divergent = specific error (`geology_context_unavailable`/`geology_context_stale`, 409) **before** calling the provider and before checking the key; the UI offers to retry without geology (explicit). A client without context can use M8 even if the server has it. The single validator was moved to `shared/geology/context.ts` (web re-exports; the server does not import `apps/web`).
7. **Vercel.** `vercel.json`: `functions."api/ai.ts".includeFiles` limited to the two files. `scripts/check-vercel-function.mjs` exercises loading and validation in the packaged function (409 for a foreign fingerprint, 503 with the correct one without a key), and absence/corruption in an isolated copy, running from an empty directory so that the cwd does not mask missing files. Before isolating, it materializes links and filePathMap entries declared by Vercel (FileFsRef outside .func), with verified paths; it does not add files absent from the manifest.
8. **Export.** New wrapper `analogos-mission-geology-export` v1 that embeds the M8 export 1.0 intact + `geology_guidance` (mode, identity, validatable subset per sector with the M9 contract, catalog, selection, provenance of the same call). Independent validator that recalculates catalog, selection and guidance, audits M8 and, with a bundle, anchors geometries and reconstructs the full result; explicit acceptance of formats (`detectMissionExportFormat`). The M8 exports 1.0 continue to validate and gain no fields.

## Limits

- No field validation or planetary equivalence validation; M9 thresholds are provisional. The AI's selection is prioritized guidance, not a measurement; exact model stability is not assumed (two real opt-in tests with contrasting objectives record whether it differs).
- The web does not verify the byte SHA-256; the wrapper declares the identity of the full package without being able to recalculate it (it only carries the sectors used).
- The prompt with geology weighs ≈ 29 000 input tokens in the final full-catalog contrast (and 6795 in the AR6 test). Latency/cost not optimized.
- Real Vercel function verified in Actions 43664952053: two filePathMap entries materialized; snapshot/geology loading and negative cases correct before publishing.
