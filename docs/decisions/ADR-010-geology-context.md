# ADR-010 — Official geological context per sector (independent package)

- Status: **accepted by Codex** after independent review of data, code, tests and browser, dev publication, and remote AI regression. See `../CODEX_M9_REVIEW.md`.
- Date: 2026-11-14
- Authorization: Dan approved the `docs/GEOLOGY_FEASIBILITY.md` cut. Codex approved the phase A plan with the corrections recorded below as "approved by Codex".

## Decision

1. **Independent package** `artifacts/geology-context-v1/index.json` with contract `contracts/geology-context.schema.json` (v1). `science-v2`, `science-v3`, profiles, scores and M8 are not touched. No lithological map, filters, geological score or geological AI.
2. **Sources** (no credentials; https only, towards two hosts): SERNAGEOMIN distributed by MMA (1:1.000.000, CC0 as declared by CKAN) and SEGEMAR/SIGAM `sigam:e250K_UnidadGeologica` (1:250.000, CC BY 4.0 as declared by the geoservices page; no additional license invented). Scale is stored as a denominator, never as resolution.
3. **Chile**: `package_show` is read from CKAN and the real content of each ZIP is inspected in memory (not extracted to disk; a single member, safe name, cap on bytes and compression ratio). The catalog's format labels are not taken as true: the first resource whose content is GeoJSON is used, and real Shapefiles are recorded as rejected (they are not parsed; no pyshp/GDAL/GeoPandas). The package narrative describes only what was observed in that acquisition: in the actual run, the resource labeled "SHP" contained GeoJSON and was used; the other resource was not downloaded. The license is read from `license_id` in CKAN and the build is rejected if it is not `cc-zero` (there is no fixed label).
4. **Argentina**: one WFS 1.0.0 GetFeature request per sector, GeoJSON, explicit `srsName=EPSG:4326`, exact sector bbox, `maxFeatures=2000`, without `resultType=hits`. Chile and Argentina share the geometric check before the cache is installed: Polygon/MultiPolygon structure and **every vertex** 2D, finite and within lon/lat range, validated before Shapely (bounds do not detect an internal NaN or malformed leaves). Required: `numberMatched == numberReturned == len(features)`, rejection if the limit is reached, CRS `urn:ogc:def:crs:EPSG::4326` (with zero features GeoServer returns `crs: null`: this is valid because there are no coordinates), lon/lat ranges, and that each feature's bbox intersects the query (this reveals swapped axes). **BBOX returns complete polygons** that may extend far outside the query: their vertices are not required to be inside; they are clipped afterwards. Features with a coincident bbox and no positive intersection are valid.
5. **Raw cache** ignored `data/raw/geology-context-v1/`: responses as-is, exact request + SHA-256, of bytes, HTTP status and real `acquired_at`. Never error bodies or headers. File names and symbolic links are checked before opening (opened without following links); roles, types, UTC dates, hashes and undeclared files must be consistent. A valid cache rebuilds without network; changing the request, geometry (even 1e-9°), hash or content invalidates it. **Transaction**: the new cache (if there was a download) and the package are prepared in sibling directories; the index is built and validated (schema and semantics, also re-read from disk) before installing anything, and then cache and package are replaced as a pair with rollback (`publish`; cache first). An HTTP, parsing, contract or publication error leaves the previous cache and package in place. Limit, as in ADR-004:: no atomicity against a power cut or `kill` between the renames; hidden `.previo` directories and mixed destinations may remain, and if a rollback fails the message describes the real state. A valid cache is reused without copies. There is no build time in the package: the dates are those of acquisition, so that the offline rebuild is byte-for-byte identical.
6. **Link to the snapshot and to the acquisition — decision approved by Codex that replaces the hash detail of the plan.** A hash of coordinates rounded to 6 decimals and a hand-rolled SHA-256 in JS are rejected. The package keeps the **exact geometry with all rings and numbers**, and Python and web require strict numeric structural equality against `candidate-details.json` (in addition to `site_id`, country and `snapshot_version`); a change < 1e-6° is detected (tested down to 1e-12°). The SHA-256 of the `candidate-details.json` file is provided as provenance and is verified in the pipeline and in the packager by reading bytes; the web does not need its own cryptography. No non-cryptographic fingerprint was added. Provenance per sector is checked in the semantics (reproducible in the web without cryptography): an Argentine sector cites exactly ONE WFS request with role `argentina_wfs`, its own `site_id` and an exact-form URL whose bbox, parsed numerically without rounding, is that of the sector; a Chilean sector must cite the download of the layer (the CKAN metadata may be additional); `request_id` is the SHA-256 of method+URL (Python recomputes it). `policy` must match the current policy and the accepted repairs must satisfy the three limits.
7. **Areas**: validity and repair on the original lon/lat coordinates; afterwards the vertices are projected to EPSG:6933 (equal-area cylindrical) and **all clipping and overlay are done in that plane**, with straight edges in it. *Engineering decision by Claude, approved by Codex in review A*: the audit operated in lon/lat and measured in 6933; when tested, the areas stopped being additive (~2e-7 of the sector, ~90 m²) because an edge that is straight in degrees is not straight after projection, and the closure of the partition failed. Operating in the plane yields exactly additive areas; the effect relative to the audit is ≤ 5e-5 percentage points. In a sector of ~0,2° the difference in edge interpretation is tens of meters, far below the scale 1:250.000/1:1.000.000.
8. **Partition without renormalizing**: `unmapped + covered_unambiguous + covered_ambiguous + unusable_upper_bound = 1` (tolerance 1e-9, checked in the contract) and `covered_total = unambiguous + ambiguous`. Units grouped by source identity (CL: code, lithostratigraphy, lithology; AR: sheet, code, name, description), dissolved (duplicates do not add up). Ambiguity = intersections between distinct units. `covered_by_units_without_description` (empty or `*`) is visible. No categories are inferred.
9. **States (approved by Codex)**, derived only from the fractions and recalculated in validation: `no_coverage` only without positive-area intersection (numeric floor 1e-6 m², floating-point noise); `available` only with complete coverage (tolerance ≤ 1e-8), without ambiguity, without rejected features or missing descriptions; minimal positive coverage is `partial`; 0 coverage with an unusable zone is `unavailable`. **99 % is never complete**: Chilean sectors with gaps or overlaps are `partial`. The states describe evidence, never suitability.
10. **Repair (provisional engineering thresholds approved by Codex; they are not a scientific standard)**: for each invalid feature `make_valid` and `buffer(0)` are computed; both must yield valid non-empty polygons (the dimensional discard of `make_valid` is recorded). Their clippings to the sector are compared with the symmetric difference and **independent** limits are applied: ≤ 0,1 % of the feature's clipped area, ≤ 0,05 % of the sector's area and ≤ 0,1 % change between the original TOTAL area and the repaired one (if the original is not positive and finite, it is rejected). The symmetric contrast between methods is computed and recorded even if another criterion already rejects. The invalid original is never clipped. If a feature is rejected, its **bbox∩sector is subtracted from all units** as a conservative mask (`unusable_upper_bound`, upper bound), so that no overlapping unit is shown as certainty there. Geometry errors when clipping follow the same path. A structure impossible to process fails the build with an explicit error, keeping the previous package.
11. **Dependency**: `shapely>=2.2,<2.3` (2.2.0 audit; Shapely/GEOS/pyproj versions in `processing`). requests/pyproj already existed. Geological APIs only in the pipeline, never in the browser.

## Actual results (first run, see `project/M9_PROGRESS.md`)

Chile 1–3 and Yungay: `partial` (99,07–99,39 % covered, 0,56–1,18 % ambiguous). Argentina 4: `partial` (50,0 %). Argentina 5: `no_coverage`. Argentina 6: `available` (100 %). These are outputs of the calculation; the feasibility audit is an independent check and agrees within 5e-5 percentage points.

## Limits

- Regional cartography, not outcrops or surface condition. Coverage ≠ precision, confidence, suitability or planetary compatibility. The score keeps "Uncalibrated geology".
- Survey date unknown (`map_date: null`); the CKAN catalog update date is not geological and goes in `catalog_modified_at`.
- Gaps are not filled with 1:1M or 1:2,5M. The verification questions are editorial guidance, not measurements.
- Straight edges in the equal-area plane; areas are not exact geodesic. Provisional thresholds; no scientific field validation.
- The M8 AI did not consume geology when M9 was accepted. *Superseded by M10 (ADR-011): the explanation may consume it only with opt-in; the package and its contract do not change.*

## Phase B — product, export and portable package

12. **Module structure**: the constants and pure rules (provisional policy, allowed URLs, `availability`, `request_digest`, `aoi_bounds`) live in `pipelines/geology_policy.py`, without Shapely, numpy, pyproj or requests. `pipelines/geology_contract.py` (JSON Schema + semantics) depends only on that module and on `jsonschema`. The packager imports it lazily and only if the build includes the package; it does not copy the semantics.
13. **Compact, expandable card** "Geological context" in the existing card, with evidence states, honest rounding, visible 1:1M/1:250K scale, units with original description, source and verification questions (editorial guidance). Texts: regional cartography, coverage ≠ precision/confidence/suitability, the "Uncalibrated geology" score does not change and the context does not imply calibrated planetary compatibility. No map of geological polygons or filters.
14. **Optional web loading** with a timeout that includes reading the body, a cap of 2 MB and full validation (TypeScript mirror of the Python validator: exact geometry, provenance per sector, fractions, recalculated state, policy, allowed https URLs). The web does not make requests to geological providers nor compute SHA-256. Absence, slowness or invalidity ⇒ "not available" without affecting selection, ranking or M8. Python and web reject the same false links and inconsistent fractions (tests with the same mutations on both sides).
15. **Independent geological export** `<site_id>-geology-context.json`, self-contained contract `geology-export` (subset of one sector with the necessary requests, source and metadata; the hash of the full candidates file is named `full_candidates_file_sha256` and it is declared that the subset is not that file). Validated in Python and web before delivery; parity fixed with a reference export. It does not modify M8 or candidate contracts.
16. **Packager**: optional `geology-context-v1/index.json`, the only file allowed in its folder, fully validated and against the bytes of the build's `candidate-details.json`; deterministic, repeatable ZIP; raw/research outside the bundle. Builds without the folder continue to be packaged as before.

## Known gaps

- The web does not verify SHA-256 (neither candidates nor `request_id`): the pipeline and the packager do. These hashes verify the link to the candidates' bytes and the request; they are not an authenticity signature nor do they replace recalculating the areas from the sources. Internally consistent alterations of other values require that additional check.
- A geological package that is present but invalid makes packaging fail (it is not relaxed); in the browser it only shows "not available".
- Local browser review, 390 px mobile, keyboard, real validated download and offline ZIP completed by Codex; evidence and limits in `../CODEX_M9_REVIEW.md`.
- No field validation; provisional thresholds. (The M8 AI did not consume geology in M9; see ADR-011 for M10.)
